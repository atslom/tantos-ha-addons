# Tantos Jolli Archive (Home Assistant add-on)

Удалённый доступ к архиву записей видеопанелей **Tantos Jolli** (XiongMai/Sofia)
прямо из Home Assistant: список по каналу и типу (вызов/движение) с реальными
датами, просмотр клипа с наложением (канал + дата-время), скачивание 1 файла или
zip, кэш с лимитом размера/срока. Список клипов авто-обновляется (интервал
настраивается), панель доступна в сайдбаре всем пользователям (не только админу).

## Установка (локальный add-on)

1. Скопируйте папку `tantos_jolly_archive/` в `/addons/` на хосте Home Assistant
   (через Samba/SSH add-on), либо распакуйте туда этот архив.
2. **Settings → Add-ons → Add-on Store → ⋮ → Check for updates**.
3. В разделе **Local add-ons** откройте **Tantos Jolli Archive → Install**.
4. На вкладке **Configuration** укажите:
   - `hub_ip` — IP хаба Tantos (напр. `192.168.0.27`);
   - `hub_user` / `hub_pass` — учётные данные telnet root вашего хаба;
   - `self_ip` — IP самого Home Assistant (куда хаб отдаёт поток, напр. `192.168.0.32`);
   - `cache_max_gb` (по умолч. 20), `cache_retention_days` (30);
   - `refresh_sec` (по умолч. 90) — интервал авто-обновления списка клипов.
5. **Start**. Откройте веб-интерфейс (сайдбар «Tantos Архив» или **Open Web UI**).

Те же параметры (IP хаба, кэш, видимые каналы, интервал обновления) можно менять
прямо в приложении — кнопка **⚙** справа вверху; они сохраняются в
`/data/app_settings.json`.

## Привязка клипов к каналам (SD-независимая)

Привязку «файл .bin → канал» ведёт сам хаб в своём индексе (QVFS): в активном
`indexNNN.bin` таблица **QVBK** хранит на каждый файл номер канала (`+0x24`) и флаг
размещения (`+0x06`). Add-on читает это **вживую при каждом обновлении**
(`hub.channel_files`): находит активный индекс по открытому файловому дескриптору
процесса Sofia (не захардкожено — индекс ротируется посуточно), парсит QVBK и
сканирует область CLUS только у размещённых файлов.

Поэтому **ничего не захардкожено и не требует ручной трассировки**: поменяли SD,
добавили панель/камеру или кольцевой буфер переназначил файлы — при следующем
обновлении (авто по `refresh_sec` или кнопка ⟳) карта перечитывается из индекса
хаба. Последняя карта кэшируется в `/data/qvbk_map.json` как резерв на случай
недоступности хаба. Канал-ордината (QVBK `+0x24`) соответствует порядку
Панель 1–4 (0–3) / Камера 1–4 (4–7). Технические 0-секундные CLUS-маркеры (end=start)
в список не выводятся — хаб их тоже не показывает.

## Требования / примечания

- Хаб должен быть доступен по telnet (root); `self_ip` — адрес HA в той же сети.
- Контейнер: `python:3.12-slim-bookworm` + `ffmpeg` (ставится при сборке).
- `host_network: true` (хаб отдаёт поток по nc на `self_ip`), `ingress: true`,
  `panel_admin: false` (панель видна всем пользователям, не только админам).
- Мелкое состояние (карта QVBK, настройки, БД «просмотрено») — в `/data`,
  переживает перезапуск и **попадает в бэкап** (оно крошечное).
- **Кэш видео** (клипы mp4 + подкачанные .bin) — в `/share/tantos_jolly_archive/`
  (НЕ в `/data`), поэтому **в бэкап add-on не входит** и не раздувает его. Кэш
  восстанавливается сам при обращении; лимит размера/срока — в ⚙.
